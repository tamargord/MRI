# Project working instructions

- Commit changes frequently, after each coherent piece of work is complete and checked, as requested by the project owner.
- Use descriptive commit messages that explain the change. Do not create empty commits or invent a history of work that was not performed.
- Keep the README and SRS consistent with actual implementation and verified results.
- Push completed commits to the configured GitHub remote when authentication is available. Do not force-push or rewrite published history without explicit authorization.
- Do not include credentials, local IDE workspace state, compiled classes, or unrelated files in commits.
